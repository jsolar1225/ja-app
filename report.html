1. 프로젝트 개요

항목내용
프로젝트명문장으로 배우는 일본어 (블록 일본어)
개발 목적단어 암기식이 아닌, 명사 + 조사 + 술어를 블록 조립하듯 익히는 일본어 문장 학습 앱
타겟 사용자JLPT N5~N1 수험생 및 일본어 초·중급 학습자

기술 스택HTML5 · CSS3 · Vanilla JavaScript · Web Speech API(TTS) · Google Fonts · localStorage
개발 방식반복적 대화형 개발 (사용자 요청 → AI 코드 제안 → 적용 → 화면 확인 → 검토·수정)

1.1 기획 배경

기존 단어장 방식 학습은 "단어는 아는데 문장을 못 만드는" 한계가 있습니다. 이를 해결하기 위해 문장을 주어 / 조사 / 술어의 3개 블록으로 분해해 보여주고, 각 블록이 조립되어 하나의 문장이 되는 과정을 시각적으로 학습하는 콘셉트를 기획했습니다.

1.2 핵심 기능 정의

기능설명
문장 동적 생성명사·동사·い형용사·な형용사·부사 5종 술어로 문장을 동적 생성 (JLPT 레벨 데이터 기반)
성분 분석 카드주어(보라) / 조사(핑크) / 술어(초록) 3칸 색상 구분 — 일본어·읽기·한국어 뜻 동시 표시
레벨 필터전체 / N5 / N4 / N3 / N2 / N1 — 레벨별 색상 강조 (초록→보라 그라데이션)
방향 전환일본어→한국어 ↔ 한국어→일본어, 버튼 1개 토글 방식
활용표동사·형용사의 활용형을 2열 그리드 카드로 표시 (모바일 1열)
발음 (TTS)문장·주어·술어 클릭 시 일본어 음성 재생
자동 다음 타이머1/3/5/10/20/30초 간격 자동 진행 + 진행바 시각화 신규 개발
진도·통계학습 완료 / 🔥오늘 학습 — localStorage 영구 저장, 진도 초기화

2. 개발 단계별 상세 기록

2.1 모드 전환 단순화 UI 개선

문제: 「일본어→한국어」「한국어→일본어」 버튼 2개가 상단 공간을 과도하게 차지.

해결: 버튼 1개로 토글하는 구조로 변경. 클릭할 때마다 라벨과 학습 방향이 동시에 전환되는 toggleMode() 단일 함수로 정리.

2.2 일본어 명조체 웹폰트 디자인

학습용 일본어 문장의 가독성을 위해 Google Fonts의 Noto Serif JP(명조체)를 도입. 문장·단어·활용형·루비(요미가나)에 serif 패밀리를 일괄 적용해 서체를 통일했습니다.

2.3 자동 다음 타이머 — 핵심 신규 기능 기능 개발

요구사항: 다음 버튼을 누르지 않아도 설정한 간격(1~30초)마다 카드가 자동으로 넘어가는 기능.

  • UI: 모드 전환 버튼 옆 흰색 긴 타원형 캡슐 안에 ⏱ 라벨 + 시간 버튼 6개 + 끄기 버튼
  • 로직: setAutoTimer() / startAutoTimer() / stopAutoTimer() 3함수 구조
  • 진행바: 다음 버튼 하단에 보라색 4px 바가 requestAnimationFrame으로 좌→우 차오르며 잔여 시간을 시각화
  • 설정 저장: 간격을 localStorage에 저장해 새로고침 후에도 유지, 복원 시 버튼 활성 상태까지 재현
  • 카운트 연동: 자동 넘어감도 수동과 동일하게 next()를 재사용해 학습 통계가 정상 +1

2.4 레이아웃 재배치 레이아웃

사용자 요청에 따라 요소 순서를 재배치했습니다:

변경 전: 헤더 → [통계] → 모드/타이머 → 술어 → 레벨 → 카드...
변경 후: 헤더 → 술어 → 레벨 → 모드/타이머 → 진행바 → 카드 → 초기화 → [통계: 최하단]

블록 이동 중 태그 짝 불일치 사고 위험을 인지하고, 이동 후 전체 태그 검증 절차를 거쳤습니다.

2.5 전체 정렬 통일 UI 개선

문제: 행마다 좌우 폭이 제각각이고 줄 간격이 울퉁불퉁함. 스크린샷 분석으로 확인.

해결:

  • 모든 행(술어·레벨·모드·진행바·카드·통계)에 width: 100% 강제 → 카드 좌우선 일치
  • 행 간격 10~14px로 균일화
  • 모드줄 justify-content: space-between → 전환버튼=좌측 끝, 타이머 캡슐=우측 끝 배치
  • 술어·레벨 버튼 min-height: 48px + 세로 중앙정렬로 버튼 높이 통일
  • 모바일(480px 이하)에서는 세로 스택 + 캡슐 중앙정렬로 전환

2.6 CSS 기술 부채 정리 코드 품질

반복 수정 과정에서 누적된 중복·충돌을 전수 조사해 통합본으로 재작성했습니다.

💡 교훈: CSS에서 동일 선택자가 여러 번 정의되면 나중 규칙이 이긴다. 파일을 여러 번 덮어쓰는 개발 방식이라면 주기적인 통합 정리가 필수다.

2.7 레벨 버튼 간소화 — 4단계 트러블슈팅 대표 사례

이 프로젝트에서 가장 많은 반복이 필요했던 이슈로, 웹 개발의 대표적 함정들을 모두 겪은 사례입니다.

발견된 문제영향조치
#conjBox.show 2회 정의뒤의 display:block이 2열 그리드를 덮어씀통합 → 2열 그리드 복원 (420px 이하만 1열)
활용박스 스타일 2세트 중복의도 불명 스타일 충돌단일 세트로 통합
.pred-btn.active#predAdv 2회파스텔 컬러 취지 무시됨1개로 정리
단계상황원인 진단해결
1차2줄(레벨명+숫자) 표시 시도 → 한 줄로 붙음flex 컨테이너 안의 \n은 기본 무시됨white-space: pre-line 추가
2차수정했는데 화면 변화 없음캐시 버전(?v=65) 미갱신 — 예전 CSS 재사용버전 파라미터 갱신 습관화
3차「숫자 자체가 불필요」로 요구 변경HTML의 숫자 제거레벨명만 남김
4차HTML·CSS를 고쳐도 숫자가 되살아남app.js의 updateLevelCounts()가 실행마다 버튼 텍스트를 다시 씀해당 함수를 레벨명 전용으로 교체 → 근본 해결
💡 교훈: UI에 나타나는 텍스트는 HTML(정적), JS(동적), CSS(표시 방식) 3계층 중 어디서 결정되는지 먼저 특정해야 한다. 특히 JS가 동적으로 다시 쓰는 값은 HTML 수정만으로는 사라지지 않는다.

2.8 통계 카드 간소화

「전체 문장」 카드를 삭제하고 「학습 완료」/「🔥오늘 학습」 2카드로 축소. index.html 카드 제거와 updateStats() 갱신 코드 정리를 동시에 수행해 존재하지 않는 DOM 요소에 쓰는 코드를 남기지 않았습니다.

2.9 기타 이슈

  • 파일 첨부 실수 사건: 중간에 태양광 발전 회사 랜딩페이지가 japanese-app 폴더의 index.html을 덮어쓴 사건 발생 → 프로젝트 폴더 분리·백업(VS Code 타임라인)의 중요성 확인. 첨부 전 파일 열어 확인하는 습관 필요
  • 캐시 버전 관리: CSS를 고쳐도 ?v=65에 머물러 있어 변경이 화면에 안 보이는 상황 반복 → v70까지 단계적 갱신

3. 주요 기술 포인트

  • requestAnimationFrame 타이머: setInterval 대신 rAF로 부드러운 진행바 렌더링. cancelAnimationFrame으로 모드 전환·카드 전환 시 잔존 타이머를 확실히 정리
  • localStorage 영속화 3종: 학습 진도, 오늘 학습 수(날짜 기준 리셋), 자동 타이머 설정 — 모두 서버 없이 유지
  • Web Speech API: speechSynthesis + ja-JP 음성으로 추가 라이브러리 없이 발음 구현
  • 동적 문장 생성: 데이터(주어·목적어·술어)와 생성 로직을 분리해 data-*.js만 추가하면 문제은행 확장 가능
  • 캐시 버스터: style.css?v=N 파라미터로 배포 시 즉시 반영
  • 반응형: 768px 이상(넓은 카드) / 480px 이하(세로 스택·버튼 축소) 2단계 대응

4. 성과 요약

배운 점 4가지

  1. 렌더링 주체 찾기: 화면의 텍스트는 HTML일 수도, JS가 쓴 것일 수도 있다 — 수정이 "안 먹히면" 렌더링 주체부터 확인
  2. CSS 캐스케이드: 중복 정의 시 나중 규칙이 이긴다 — 통합 정리가 품질의 핵심
  3. 캐시 버전 관리: 수정 후 화면이 안 바뀌면 코드가 아니라 캐시를 먼저 의심
  4. 파일 관리: 프로젝트별 폴더 분리와 첨부 전 확인으로 치명적 덮어쓰기 사고 예방
