앱 제작 커맨드 노하우 — 기획부터 배포까지

1부. AI 커맨드(프롬프트) 노하우 — "한 번에 만드는" 비밀

1-1. "커맨드 1번으로 만든다"의 실체

유형설명
아주 간단한 앱계산기, 투두리스트 수준 — 진짜 1번에 가능
보이지 않는 반복 수정영상에는 1개 커맨드만 보이지만 실제로는 수십 번 다듬은 결과
검증된 프롬프트 재사용이미 완성해둔 상세 기획서를 그대로 붙여넣는 것

"1번 커맨드로 만드는 사람은, 그 1번에 다 쓸 수 있게 기획서를 몇 시간 써둔 사람이다."

1-2. 1번에 가깝게 만드는 노하우 5가지

① 프롬프트에 "기획서"를 넣는다 (가장 중요)
❌ 나쁜 예: 일본어 학습 앱 만들어줘
✅ 좋은 예: 데이터 형식 / 화면 구성 / 버튼 동작 / 기술 조건을 전부 명시 (3부 기획서 참고)
② "하지 말 것"도 명시한다
예: 외부 라이브러리 금지 / addEventListener 사용 / alert 대신 화면 내 메시지
③ 파일 구조와 이름을 미리 지정한다
예: index.html / css/style.css / js/app.js 3개 파일로 분리 — 구조 붕괴·경로 문제 예방
④ 1번 = 뼈대, 이후 = 다듬기로 생각한다
커맨드 1회 → 실행 확인 → 에러/개선점만 모아 한 커맨드로 전달.
에러 메시지를 통째로 복사해서 주는 사람이 가장 빠르다.
⑤ 도구를 상황에 맞게 고른다
도구특징적합한 상황
Cursor / Claude Code코드 파일 직접 읽고 수정기존 프로젝트 개선
v0 / Lovable / Bolt설명·스샷 → 웹앱 생성신규 간단 앱
채팅 AI + 복붙직접 파일 관리학습 목적, 소규모

2부. 제작 순서 노하우 (실패 경험에서 정리)

2-1. 제작 순서 6단계

단계할 일지킬 때의 이점
① 기획화면 목록, 핵심 기능 5개 이내 정의 (문서로!)버튼 반복 수정, HTML 깨짐 방지
② 데이터 설계데이터 형태를 먼저 확정 (필드·역할 등)"이 필드 뭐였지?" 반복 수정 방지
③ 목업HTML+CSS만으로 화면 1장 먼저 완성태그 오류·CSS 로드 문제 사전 차단
④ MVP최소 동작 버전부터 (카드 1장 + 버튼)데이터 없이도 로직 검증
⑤ 기능 추가하나씩 추가 → 확인 → 저장 → 다음원인 추적이 쉬움
⑥ 배포마지막에 배포—

2-2. 실패 → 대응법 5가지

📄 고치기 전에 백업 — 버전 폴더 복사(app_v62.js) 또는 Git. 버전 꼬임의 80%는 롤백 불가에서 온다.
✏️ 수정은 한 번에 한 기능 — 고치고 → 새로고침 확인 → 다음. 동시 수정이 에러의 주원인.
🏗️ HTML 수정 후 구조 검증 — VS Code 확장「HTML tag checker」또는 F12 → Elements 탭에서 태그 경고 확인. (닫는 태그 하나가 레이아웃 전체를 무너뜨린다)
🔧 공통 로직은 함수 하나로 — 같은 규칙이 여러 곳에 복사되면, 함수 하나를 만들어 호출하게 한다. 수정은 1곳만.
🖥️ 콘솔 로그를 습관으로 — "안 된다" → F12 Console 먼저. 에러 메시지의 줄 번호가 정답을 알려준다.

2-3. 배포 방법 (10분)

방법절차
GitHub Pages
(무료, 추천)		github.com 가입 → 새 저장소 생성 → 앱 폴더 전체 업로드(드래그&드롭) → Settings → Pages → Branch: main → Save → 1~2분 후 https://아이디.github.io/저장소명/
Netlify Drop
(가장 쉬움)		netlify.com 접속 → 폴더 드래그&드롭 → 즉시 배포

⚠️ 웹 배포 후에는 ?v=42 같은 쿼리가 캐시 갱신에 도움됨.

3부. 기획서 실전 예시 — 일본 태양광 뉴스 자동 수집·번역 앱

⚠️ 법적 주의 (기획 첫 줄)
뉴스 본문 전문 게시 = 저작권 침해. 합법 구성: 제목 + 원문 링크 + 짧은 자체 요약 + 출처 명시.
(제목·링크·언론사명·시각 표시 ✅ / 본문 전문 복사 ❌ / 기사 사진 ❌)

3-1. 한 줄 정의

「일본 뉴스에서 태양광/재생에너지 기사를 자동 수집 → 헤드라인 한국어 번역 → 하루 1~4회 웹페이지에 자동 게시하는 앱」

3-2. 핵심 기능 5개

기능도구난이도
수집 — RSS로 헤드라인 수집 (太陽光, ソーラー, FIT, FIP 필터)Python + feedparser (NHK, 日経 등 RSS)쉬움
번역 — 헤드라인 자동 한국어 번역Google 비공식 API(무료) / DeepL API(월 50만자 무료)중
게시 — 제목·번역·언론사·시각·원문 링크 목록HTML/CSS/JS 1페이지쉬움
자동화 — 일정 시간 자동 실행GitHub Actions (cron 예약, 무료)쉬움
저장 — 과거 뉴스 누적news.json 누적 커밋쉬움

3-3. 아키텍처 — 서버 비용 0원

[GitHub Actions: 매일 7시/12시/19시 자동 실행]
        ↓
 Python 스크립트: RSS 수집 → 키워드 필터 → 번역 → news.json 생성
        ↓
 news.json을 저장소에 자동 커밋
        ↓
[GitHub Pages 웹페이지]가 news.json 읽어 표시 (접속 시 항상 최신)

3-4. MVP 제작 순서

단계만들 것확인 기준
①Python 스크립트: NHK RSS → 태양광 기사 제목 출력콘솔에 제목 찍힘
②번역 추가: 제목 → 한국어 출력일본어+한국어 출력
③news.json 생성파일 내용 확인
④웹페이지: news.json 읽어 목록 표시브라우저에서 목록 보임
⑤GitHub Actions + Pages 배포매일 자동 갱신
⑥(나중) 요약, 키워드 설정, 즐겨찾기—

💡 ①~④까지만 해도 「PC에서 실행하면 뉴스 페이지」 완성. ⑤는 배포 단계.

3-6. 첫 커맨드 예시 (복사해서 사용)

일본 태양광 뉴스 수집 앱의 1단계를 만들어줘.

[요구사항]
- Python 스크립트 1개 (collect.py)
- feedparser로 NHK 뉴스 RSS 수집
- 제목에 太陽光 / ソーラー / 再生可能 에너지 키워드 포함 기사만 필터
- 출력: 일본어 제목, 링크, 게시 시각
- 외부 라이브러리는 feedparser만 사용

[하지 말 것]
- 기사 본문 수집 금지 (저작권) — 제목과 링크만

💡 핵심 한 줄: "기획서가 곧 첫 커맨드다 — 화면 먼저, 데이터 먼저, 기능은 하나씩."
